# CRUD-RAG 中文问答测试集（20 题）


从 [CRUD-RAG 官方实验子集](https://github.com/IAAR-Shanghai/CRUD_RAG/blob/main/data/crud_split/split_merged.json) 中选取 20 道中文问答：单篇 10 题、双篇 6 题、三篇 4 题。题目与参考答案保留原文。适合先验证检索、答案生成和评测流程。

## 文件用途

| 文件 | 用途 |
| --- | --- |
| `questions.json` | 测试集，包含题号、问题、参考答案、配套文档名；兼容项目的 `GoldenDataset.load()` 读取结构 |
| `题目清单.md` | 便于直接阅读的 20 道题和参考答案 |
| `corpus/` | 34 篇配套新闻原文，作为检索知识库输入 |
| `original_records.json` | 保留选中样本的全部官方字段，便于追溯 |
| `manifest.json` | 官方任务类型、原始 ID、从 0 开始的数组索引、校验值及筛选记录 |

## 在测试平台中使用

1. 将 `corpus/` 中的文档导入专门的中文测试知识库并建立索引。测试这些新闻题需要配套新闻语料，现有 FastAPI 文档知识库不包含这些答案。
2. 从 `questions.json` 的 `questions` 数组读取测试题：`id` 是题号，`question` 是输入，`answer` 是参考答案，`source_documents` 是相关文档名。
3. 先做本地检索时，逐题检查相关文档是否进入召回结果，以及排序位置；不需要模型 API。双篇、三篇题可额外检查多份相关材料的召回情况。
4. 做答案生成时，再接入你的生成模型。答案及评审可使用本地模型；本次选题和文件校验没有调用模型 API。

只将 `corpus/` 导入检索知识库。`questions.json`、题目清单和原始记录包含参考答案，应用作独立评测资料，避免答案泄漏。

`source_documents` 中的文件名相对于 `corpus/`。每份文档仅增加了本地 Markdown 标题“正文”，以对应 `source_sections`，标题后的新闻内容保留原文。

## 如何理解结果

- 这是学习用小样本，不是完整官方基准。配套的 34 篇原文没有包含官方完整检索语料，所得分数不能与完整基准直接比较。
- 官方的单篇、双篇、三篇标签表示提供的新闻篇数。多篇内容可能重复，不保证每道题都必须使用全部文档，也不能直接视为严格多跳推理。
- 为兼容本项目，单篇映射为 `lookup`，双篇和三篇映射为 `multi_hop`；官方任务标签完整保存在来源记录中。
- 本集合没有无答案题、歧义题，因此不能据此判断系统拒答能力。
- 经过候选抽取和人工筛选，排除了若干明显的时间、地点或证据问题。没有重新标注或改写官方参考答案；原始语料仍可能包含重复和抓取噪声。
- 项目现有 `GoldenDataset.validate()` 针对原来的完整测试集，要求至少 50 题且四类齐全。这份 20 题子集能被读取，但不满足该校验策略；本次未修改校验规则或评测入口，也未运行模型评测。

源文件快照保存在项目 `.local/crud-rag-source/split_merged.json`。其 SHA-256、选择日期和最终样本索引均记录在 `manifest.json` 中，便于复核。

## 已接入本地 Evals.si 平台


- `evalsi_records.json`：平台界面可上传的 JSON 记录数组。
- `evalsi_publish.json`：向平台发布此版本所用的完整请求内容。
- `evalsi_integration.json`：导入结果、固定版本引用及回读校验记录。

字段映射为 `question → input.text`、`answer → reference.text`，原始任务类型、题号和配套文档名放在 `metadata` 中。没有将参考答案填入模型输出，也没有把配套原文当作实际召回上下文；原文仍需导入 RAG 的检索知识库。

初次导入时仅接入测试集，没有启动评测。后续评测记录见下文。详情页默认的精确匹配不适合单独衡量这类中文开放式问答。

## 已完成首轮真实模型评测

已使用项目配置的 DeepSeek（`deepseek-flash`）完成 20 道题的实际 RAG 调用，最终回答 2 题、拒答 18 题，平均完整处理耗时约 10.98 秒。回答率不等于语义正确率。



初轮原始运行的长度和耗时统计出现兼容问题，因此另行发布了 `crud-rag-zh-20-results@deepseek-first-v1` 结果快照，以记录模式完成完整评分。该快照含已生成的答案，用于结果复核；生成新一轮回答时应继续使用不含模型输出的原始测试集。

公开仓库保留题目、来源和配套原文。历史本机评测汇总见仓库首页，各平台的运行编号属于各自部署环境。
